# 工业缺陷检测 Demo 开发文档

## 1. 文档信息

- 项目名称：工业缺陷检测 Demo（Inspectra）
- 当前版本：0.1.4
- 文档日期：2026-10-24
- 项目目录：`D:\000Industrial_Defect_Detection\Develop`
- 第一阶段目标：跑通创建批次、上传图片、模拟检测、人工复核、统计和 CSV 导出。
- 当前限制：检测结果来自确定性 Mock 引擎，不代表真实模型精度，不能用于生产质量判断。

## 2. 当前功能

1. 创建检测批次，记录批次名称、工件编号、检测场景和备注。
2. 查看批次列表与批次详情。
3. 上传 JPG、PNG、WEBP 图片，单张最大 10MB，单次请求最大 100MB。
4. 使用 Mock 引擎返回 OK/NG、缺陷类别、置信度、检测框和推理耗时。
5. 人工修改判定、缺陷类别和复核备注。
6. 统计批次图片总数、OK、NG 和合格率。
7. 导出 UTF-8 BOM 格式的 CSV 检测结果。
8. 使用 JSON 文件保存批次数据，服务重启后可继续读取。
9. 二次确认后删除批次，并同步删除该批次上传的图片。
10. 将批次查看、编辑和删除拆分为独立入口；查看模式不允许上传或复核。
11. 批次详情提供返回列表与查看下一条记录，并保持当前查看或编辑模式。

## 3. 技术架构

| 层级 | 当前实现 | 说明 |
| --- | --- | --- |
| 页面 | 原生 HTML、CSS、JavaScript | 与后端一起打包，无需 Node.js |
| 后端 | Java 17、Spring Boot 4 | 提供页面、批次、图片、复核和导出接口 |
| 数据 | JSON 文件 | 第一阶段不引入数据库 |
| 文件 | 本地目录 | 保存上传图片和运行状态 |
| 推理 | MockInferenceService | 后续由 ONNX 适配器替换 |
| 部署 | JAR、systemd、Nginx | 适配 4GB 内存、无显卡服务器 |

浏览器通过同源 `/demo/api/*` 调用当前 Spring Boot 后端。“后端服务正常”表示 `/demo/api/health` 返回成功，不代表连接了 AI、GitHub 或第三方平台。

## 5. 本地开发与运行

### 5.1 IDEA 打开

使用 IDEA 直接打开 `D:\000Industrial_Defect_Detection\Develop`，等待 Maven 导入完成。项目编译目标为 Java 17，Maven Wrapper 版本为 3.9.11。

### 5.2 测试

```powershell
.\mvnw.cmd clean verify
```

### 5.3 启动

```powershell
.\mvnw.cmd spring-boot:run
```

也可以执行 `start.bat`。默认访问地址：

- Demo：`http://127.0.0.1:8080/demo/`
- 进度页：`http://127.0.0.1:8080/demo/docs/`
- 健康检查：`http://127.0.0.1:8080/demo/api/health`

## 6. 接口说明

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/demo/api/health` | 检查 Spring Boot 后端状态与版本 |
| GET | `/demo/api/batches` | 查询批次列表 |
| POST | `/demo/api/batches` | 创建批次 |
| DELETE | `/demo/api/batches/{id}` | 删除批次、检测记录和上传图片 |
| GET | `/demo/api/batches/{id}` | 查询批次详情 |
| POST | `/demo/api/batches/{id}/images` | 上传图片并执行检测 |
| PATCH | `/demo/api/batches/{batchId}/images/{imageId}` | 保存人工复核 |
| GET | `/demo/api/batches/{id}/stats` | 查询批次统计 |
| GET | `/demo/api/batches/{id}/export` | 导出 CSV |
| GET | `/demo/api/files/{storedName}` | 读取上传图片 |

创建批次示例：

```json
{
  "name": "轴承外圈 2026-10-24",
  "partNumber": "BR-6205",
  "scene": "机加工金属件",
  "note": "记录来源与拍摄条件"
}
```

## 10. Git 与发布流程

默认工作流：

1. Codex 在本地修改代码和文档。
2. 本地测试通过后向用户提供预览与验证结果。
3. 用户明确确认可以提交和部署。
4. Codex 编写详细中文提交信息并提交 Git。
5. 推送 GitHub，再部署服务器并验证公网状态。

未经用户当次明确同意，不执行 Git 提交、推送或服务器部署。

提交信息格式：`类型(范围): 中文结果摘要`。正文根据实际情况使用“新增、修改、修复、验证、文档、部署”等栏目。
